# Coordinate accepted work in the queue

## In plain English

Retain the existing owner. Follow the stage boundary below and leave the next person a clear, truthful handoff.

Read [the overarching workflow](../driving-work-end-to-end/SKILL.md) and [shared authority/evidence rules](../driving-work-end-to-end/reference/system.md) first.

## Entry

Actual scoped acceptance, existing plan owner, client priority and current builder/cycle context.

## Work and permitted actions

Retain the existing owner. Recommend placement, priority and date risks privately. Capture only actual agreed readiness/start decisions; do not assign builders, invent availability, add commitments or start work. Engineering cycles are Linear initiatives grouping projects; native Cycles are unused. Several ordered Main/Flex projects are allowed.

## Exit and exceptions

Queue/readiness context and exact next owner decision. Actual pickup, rather than acceptance alone, begins In Progress.

Record actual friction and source evidence for a narrow reviewed correction. Never silently change stage semantics, approval policy, channel authority or enablement.
