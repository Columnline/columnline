# Check plan acceptance

## In plain English

Record only explicit assent to this scope/revision. Follow the stage boundary below and leave the next person a clear, truthful handoff.

Read [the overarching workflow](../driving-work-end-to-end/SKILL.md) and [shared authority/evidence rules](../driving-work-end-to-end/reference/system.md) first.

## Entry

Actual human delivery receipt, exact current work/Material revision, named authorized responder and complete source/thread/comments.

## Work and permitted actions

Record only explicit assent to this scope/revision. Questions, negation, conditional or ambiguous language and silence do not count. Checkpoint mentions are not approvals; preserve partial assent and unresolved checkpoints. Follow the shared bounded nudge policy within actual authority and reconcile unknown sends. Scope-changing feedback needs revision/review, not acceptance.

## Exit and exceptions

Actual scoped acceptance queues only this work and preserves owner/unrelated parent scope. Incorporate accepted child scope into project milestones only through the existing authorized owner decision; no automatic build or new promises.

Record actual friction and source evidence for a narrow reviewed correction. Never silently change stage semantics, approval policy, channel authority or enablement.
