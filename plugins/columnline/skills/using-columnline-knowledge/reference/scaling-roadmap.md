# Scaling Roadmap: apply the source to the business

Use for business-stage diagnosis, comparisons across stages, and “what should
I do next in the business?” questions. The Business Model base owns the framework; Founder
and client Knowledge explain the business. Live owners still decide changing
facts. A framework recommendation is not a new company policy or commitment.

## Read the complete map without guessing coverage

1. Discover the authorized Business Model base and read its Start Here page.
   Search within that base for the Scaling Roadmap navigation page, then open
   the relevant stage and cited sources. A remembered page ID is a hint, not
   proof of current access or content.
2. Keep Start Here, the high-level Context lesson, and every numbered stage
   in scope, including earlier and later stages. An edition supplied for one
   stage must not silently limit the comparison. Verify the source's current
   stage labels and order; do not invent thresholds or fill missing stages.
3. Separate each source type: original PDF/page, video link, full transcript,
   partial transcript, and analysis. Read the actual transcript before saying
   what the speaker said. A page called “Complete Index” proves only the
   coverage its current contents and linked sources support.
4. For a transcript, retain the lesson title, original video link, language,
   whether it is human or machine transcribed, timestamps where available,
   and any missing or uncertain portions. Reconcile the expected lesson
   inventory with actual transcripts and each recording’s beginning-to-end
   coverage, flagging missing lessons, intervals or uncertain alignment. A
   transcript page existing is not proof of completeness. Never fill gaps
   with imagined speech.
5. If only the PDF is available, answer from it when sufficient and say the
   video transcript was not checked. Full corpus acquisition is a separate
   task: honor the provider's rights and terms, use authorized source files or
   transcripts, and do not treat a reachable media URL as download permission.

## Diagnose, then choose the next constraint

- Do not assign the user a stage because an email or PDF selected that edition.
  Ask what that selection actually measured. A stock “personalized” cover is
  not evidence of a company-specific assessment.
- Compare the source's stage criteria against current evidence for demand,
  sales, fulfillment, retention, cash, people and management where relevant.
  Different functions can be at different stages. Revenue or headcount alone
  must not replace the source's actual diagnostic criteria.
- Reuse verified facts from the conversation and live systems. Ask only for
  missing facts that would change the recommendation, and name uncertainty
  rather than estimating a flattering or alarming stage.
- Identify the constraint most limiting the outcome. Check prerequisite work
  in earlier stages, and explain the next stage when it helps the user see
  the path. Do not recommend all stages' work at once.
- Recommend the smallest useful next action with a success measure and the
  evidence that would justify moving on. Keep ownership and dates as proposals
  unless the user already approved them; advice alone does not create tasks,
  spend money, change a system or contact anyone.

## Answer shape

Use a short answer adapted to the question, ordinarily:

- Current position: stage or range by relevant function, the evidence and gaps.
- Main constraint: why this is first, with an exact stage/page or lesson and
  timestamp citation when available.
- Next move: one action, how to tell it worked, and what comes after that.
- Source coverage: disclose any missing transcript or unverified source that
  could change the conclusion. Label analysis separately from source claims.

Keep an ordinary next-action answer focused. When the user asks for the full
roadmap or an all-stage walkthrough, deliver that overview rather than merely
offering it, while distinguishing later-stage education from present action.
Link to the maintained Knowledge pages.
